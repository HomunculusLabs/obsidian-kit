## 🎯 Core Concepts

### **Obsidian Kit**
The comprehensive CLI tool and framework for creating AI-powered Obsidian vaults with integrated project management, knowledge graphs, and workflow automation.

### **Vault**
An Obsidian workspace containing markdown files, plugins, and configuration. In Obsidian Kit, vaults are structured with specific directories for different types of content.

### **Spec-Driven Development**
A development methodology where specifications (specs) drive the entire development process, from planning to implementation to documentation.

### **Knowledge Graph**
A network of interconnected entities, concepts, and relationships extracted from vault content, enabling intelligent search and content discovery.

### **Semantic Search**
Advanced search capability that understands meaning and context rather than just matching keywords, powered by AI embeddings.

### **Workflow Automation**
Automated processes that execute predefined sequences of tasks, reducing manual effort and ensuring consistency.

## 🤖 AI & Agent Terminology

### **AI Agent**
An artificial intelligence system that can perform tasks, make decisions, and interact with users or other systems. In Obsidian Kit, agents help with task management, content creation, and analysis.

### **Claude Code**
Anthropic's Claude AI model specifically configured for code-related tasks and technical documentation.

### **OpenCode**
An AI agent integration for VS Code and similar development environments.

### **Cursor**
An AI-powered code editor and assistant.

### **MCP (Model Context Protocol)**
A protocol for enabling AI models to interact with external tools and data sources, allowing agents to access vault content and perform actions.

### **Universal Context**
Shared knowledge and context that all AI agents can access, ensuring consistency across different AI interactions.

### **Slash Commands**
Standardized commands (prefixed with `/`) that trigger specific AI agent actions or workflows.

### **Enhanced Agent Intelligence**
Advanced AI capabilities including context awareness, learning from user interactions, and adaptive responses.

## 📊 Project Management Terms

### **Task Breakdown**
The process of decomposing large tasks into smaller, manageable subtasks with time estimates and dependencies.

### **Automated Task Generation**
AI-powered creation of tasks from specifications, user stories, or other source documents.

### **Task Validation**
Automated checking of task quality, completeness, and adherence to standards.

### **Sprint**
A time-boxed period (usually 1-4 weeks) in which specific work is completed, commonly used in agile development.

### **Milestone**
Significant point or event in a project timeline, often marking the completion of major phases.

### **Backlog**
A prioritized list of tasks, features, or requirements to be worked on.

### **Velocity**
The amount of work a team can complete during a sprint, used for planning future work.

### **Definition of Done**
Clear criteria that must be met for a task or feature to be considered complete.

### **Acceptance Criteria**
Specific conditions that must be fulfilled for a user story or feature to be accepted.

## 🔧 Technical Terms

### **CLI (Command Line Interface)**
A text-based interface for interacting with software, used by Obsidian Kit for all operations.

### **API (Application Programming Interface)**
A set of protocols and tools for building software applications, allowing different systems to communicate.

### **REST API**
An architectural style for designing networked applications, used by Obsidian's local API.

### **JSON (JavaScript Object Notation)**
A lightweight data interchange format used for configuration files and API responses.

### **YAML (YAML Ain't Markup Language)**
A human-readable data serialization format used for configuration and frontmatter.

### **Frontmatter**
Metadata at the beginning of markdown files, enclosed in `---` dashes, used by Obsidian and Obsidian Kit.

### **Dataview**
An Obsidian plugin that enables querying and displaying vault data using a SQL-like syntax.

### **Templater**
An Obsidian plugin that enables powerful template creation and automation.

### **Plugin**
Add-on software that extends Obsidian's functionality.

## 📝 Obsidian-Specific Terms

### **Markdown**
A lightweight markup language for formatting text, used by Obsidian for all notes.

### **Linking**
The practice of creating connections between notes using `[[note name]]` syntax.

### **Graph View**
A visual representation of note connections and relationships in Obsidian.

### **Daily Notes**
Notes automatically created for each day, often used for journaling and daily planning.

### **Zettelkasten**
A method of note-taking and knowledge management emphasizing atomic notes and dense linking.

### **Canvas**
An infinite whiteboard space in Obsidian for visual thinking and organization.

### **Tags**
Labels used to categorize and organize content, prefixed with `#`.

### **Aliases**
Alternative names for notes that can be used in linking.

### **Workspaces**
Saved layouts and configurations of panes and tabs in Obsidian.
